# OpenPilot 车辆控制代码分析

## 概述
OpenPilot 是一个开源的高级驾驶辅助系统 (ADAS)。本文档详细分析了其车辆控制代码结构、不同车型的通信协议以及控制机制。

---

## 一、车辆控制代码架构

### 1.1 核心目录结构
```
selfdrive/car/              # 车辆控制核心代码
├── honda/                  # 本田车型
├── toyota/                 # 丰田车型

```

### 1.2 每个品牌的标准文件结构
每个车型品牌目录通常包含：
- **carcontroller.py** - 车辆控制器，发送控制指令
- **carstate.py** - 车辆状态读取
- **values.py** - 车型定义和参数配置
- **interface.py** - 车辆接口实现
- **xxxcan.py** - CAN消息打包/解包函数（如 hondacan.py, toyotacan.py）
- **radar_interface.py** - 雷达数据接口

## 二、车辆控制的核心组件

### 2.1 CarController 类（车辆控制器）
这是发送控制命令到车辆的核心类。主要功能：

#### 通用控制流程：
```python
def update(self, CC, CS, now_nanos):
    actuators = CC.actuators  # 获取执行器指令

    # 1. 转向控制
    apply_steer = actuators.steer * STEER_MAX

    # 2. 纵向控制（油门/刹车）
    if CC.longActive:
        gas, brake = compute_gas_brake(actuators.accel, speed)

    # 3. 打包CAN消息并发送
    can_sends.append(create_steering_control(...))
    can_sends.append(create_brake_command(...))

    return can_sends
```

### 2.2 主要控制输出
所有车型的控制器都需要输出以下控制信号：

1. **转向控制** (Steering Control)
   - 转向力矩 (Steering Torque)
   - 转向角度 (Steering Angle)
   - 转向请求状态 (Steering Request)

2. **纵向控制** (Longitudinal Control)
   - 油门控制 (Throttle/Gas)
   - 刹车控制 (Brake)
   - 加速度指令 (Acceleration Command)

3. **HUD/仪表显示**
   - 巡航速度显示
   - 车道线显示
   - 前车距离显示
   - 警告信息

## 三、不同车型的通信协议

### 3.1 本田 (Honda)

#### 控制架构
本田有两种主要架构：
- **NIDEC** - 老款系统
- **BOSCH** - 新款系统

#### CAN总线布局
```
Bus 0: ACC-CAN (雷达侧)
Bus 1: F-CAN B (动力系统)
Bus 2: ACC-CAN (摄像头侧)
Bus 3: F-CAN A (OBD-II 端口)
```

#### 关键CAN消息

##### 1. 转向控制 (STEERING_CONTROL)
- **消息ID**: 0x228 (NIDEC), 0xE4 (BOSCH)
- **频率**: 100Hz
- **数据字段**:
  ```
  STEER_TORQUE: 转向力矩 (-3000 到 3000)
  STEER_TORQUE_REQUEST: 转向请求标志
  ```

##### 2. 刹车控制 (BRAKE_COMMAND)
- **消息ID**: 0x1FA
- **频率**: 50Hz
- **数据字段**:
  ```
  COMPUTER_BRAKE: 刹车压力 (0-1024)
  BRAKE_PUMP_REQUEST: 刹车泵请求
  CRUISE_OVERRIDE: 巡航系统覆盖
  CRUISE_CANCEL_CMD: 取消巡航
  ```

##### 3. 加速度控制 (ACC_CONTROL)
- **消息ID**: 0x1DF (BOSCH)
- **频率**: 50Hz
- **数据字段**:
  ```
  ACCEL_COMMAND: 加速度命令
  GAS_COMMAND: 油门命令
  CONTROL_ON: 控制激活标志
  ```

#### 代码示例
```python
# selfdrive/car/honda/hondacan.py
def create_steering_control(packer, CAN, apply_steer, lkas_active, car_fingerprint, radar_disabled):
    values = {
        "STEER_TORQUE": apply_steer if lkas_active else 0,
        "STEER_TORQUE_REQUEST": lkas_active,
    }
    return packer.make_can_msg("STEERING_CONTROL", bus, values)
```

### 3.2 丰田 (Toyota)

#### 控制架构
丰田有两代主要系统：
- **TSS (Toyota Safety Sense)** - 第一代
- **TSS 2.0/2.5** - 第二代

#### 控制方式
1. **LKA (Lane Keeping Assist)** - 使用转向力矩控制
2. **LTA (Lane Tracing Assist)** - 使用转向角度控制

#### CAN总线
- 主要使用 **Bus 0** 进行控制通信

#### 关键CAN消息

##### 1. 转向控制 (STEERING_LKA)
- **消息ID**: 0x2E4
- **频率**: 100Hz (但建议42Hz以提高速率限制)
- **数据字段**:
  ```
  STEER_REQUEST: 转向请求
  STEER_TORQUE_CMD: 转向力矩命令 (-1500 到 1500)
  SET_ME_1: 常量字段
  ```

##### 2. 转向控制 - LTA (STEERING_LTA)
- **消息ID**: 0x191
- **频率**: 50Hz
- **数据字段**:
  ```
  STEER_ANGLE_CMD: 转向角度命令
  STEER_REQUEST: 转向请求
  TORQUE_WIND_DOWN: 力矩递减控制
  PERCENTAGE: 控制百分比
  ```

##### 3. 加速度控制 (ACC_CONTROL)
- **消息ID**: 0x343
- **频率**: 50Hz
- **数据字段**:
  ```
  ACCEL_CMD: 加速度命令 (-4.0 到 2.0 m/s²)
  ACC_TYPE: ACC类型
  MINI_CAR: 前车显示
  PERMIT_BRAKING: 允许刹车
  RELEASE_STANDSTILL: 释放静止状态
  CANCEL_REQ: 取消请求
  ```

#### 代码示例
```python
# selfdrive/car/toyota/toyotacan.py
def create_steer_command(packer, steer, steer_req):
    values = {
        "STEER_REQUEST": steer_req,
        "STEER_TORQUE_CMD": steer,
        "SET_ME_1": 1,
    }
    return packer.make_can_msg("STEERING_LKA", 0, values)

def create_lta_steer_command(packer, steer_control_type, steer_angle, steer_req, frame, torque_wind_down):
    values = {
        "COUNTER": frame + 128,
        "STEER_ANGLE_CMD": steer_angle,
        "STEER_REQUEST": steer_req,
        "TORQUE_WIND_DOWN": torque_wind_down,
        # ... 其他字段
    }
    return packer.make_can_msg("STEERING_LTA", 0, values)
```

### 3.3 斯巴鲁 (Subaru)

#### 控制架构
斯巴鲁有两代系统：
- **Pre-Global** - 老款平台
- **Global Platform** - 新款全球平台

#### CAN总线布局
```python
class CanBus:
    MAIN = 0
    ALT = 1
    CAMERA = 2
```

#### 关键CAN消息

##### 1. 转向控制 (ES_LKAS)
- **频率**: 50Hz
- **数据字段**:
  ```
  LKAS_Output: 转向力矩输出
  LKAS_Request: LKAS请求标志
  SET_1: 常量
  ```

##### 2. 纵向控制 (ES_Distance)
用于Pre-Global平台：
- **数据字段**:
  ```
  Cruise_Throttle: 巡航油门 (808-3400)
  Cruise_RPM: 目标RPM (0-3600)
  Cruise_Brake_Active: 刹车激活
  Cruise_Cancel: 取消巡航
  ```

#### 参数配置
```python
class CarControllerParams:
    # 转向参数
    STEER_MAX = 2047  # 或 1439, 1000（根据车型）
    STEER_DELTA_UP = 50
    STEER_DELTA_DOWN = 70

    # 油门/刹车参数
    THROTTLE_MIN = 808
    THROTTLE_MAX = 3400
    THROTTLE_INACTIVE = 1818

    BRAKE_MIN = 0
    BRAKE_MAX = 600

    RPM_MIN = 0
    RPM_MAX = 3600
    RPM_INACTIVE = 600
```

### 3.4 通用汽车 (GM)

#### 控制架构
GM使用 **ASCM (Active Safety Control Module)** 架构

#### CAN总线
- **Powertrain Bus**
- **Chassis Bus**
- **Radar/Object Bus**

#### 关键消息

##### 1. 转向控制 (ASCMLKASteeringCmd)
- **频率**: 50Hz (活动时), 10Hz (非活动时)
- **特殊要求**: 消息间隔至少 15ms 以避免故障
- **数据字段**:
  ```
  LKASteeringCmd: 转向力矩命令
  LKASteeringCmdActive: 激活标志
  RollingCounter: 滚动计数器
  ```

#### 代码特点
```python
# GM需要特殊的计数器同步逻辑
# 避免在摄像头消息传输时产生故障
if self.CP.networkLocation == NetworkLocation.fwdCamera:
    # 保持与摄像头同步
    out_of_sync = self.lka_steering_cmd_counter % 4 != (CS.cam_lka_steering_cmd_counter + 1) % 4
    if out_of_sync:
        steer_step = self.params.STEER_STEP
```

### 4.2 DBC文件作用
DBC文件定义了：
1. **CAN消息ID** - 每条消息的唯一标识符
2. **信号定义** - 每个信号的位置、长度、缩放因子
3. **值表** - 枚举值的含义
4. **消息频率** - 发送周期

## 五、安全机制（Safety）

### 5.1 Panda安全模块
Panda是OpenPilot的硬件接口，包含安全检查逻辑：

```cpp

#define SAFETY_HONDA_NIDEC 1U

```

### 5.2 安全检查
每个品牌都有独立的安全模块：
- `safety/safety_honda.h`
- `safety/safety_toyota.h`
- `safety/safety_subaru.h`
- 等等...

### 5.3 安全检查内容
1. **转向力矩限制** - 防止过大转向输入
2. **转向速率限制** - 防止转向变化过快
3. **刹车/油门互锁** - 防止同时输入
4. **驾驶员监控** - 确保驾驶员接管能力
5. **CRC校验** - 消息完整性检查
6. **计数器检查** - 防止消息丢失/重复

## 七、通信协议总结

### 7.1 CAN协议基础
所有车型都使用 **CAN (Controller Area Network)** 总线通信：
- **波特率**: 通常 500 Kbps
- **消息格式**: 标准帧（11位ID）或扩展帧（29位ID）
- **数据长度**: 0-8字节

### 7.2 消息保护机制
大多数车型使用以下保护：
1. **Checksum（校验和）** - 4或8位校验
2. **Counter（计数器）** - 2或4位滚动计数器
3. **特定字段** - 某些固定值字段用于验证

### 7.3 通信特点对比

#### 本田
- 使用多总线架构
- NIDEC和BOSCH系统消息ID不同
- 需要雷达禁用命令（tester present）

#### 丰田
- 相对简单的单总线架构
- TSS2使用LTA角度控制（更先进）
- 需要DSU模拟或禁用

#### 斯巴鲁
- Pre-Global使用按钮模拟
- Global Platform使用直接控制
- 油门使用RPM+节气门双重控制

#### 通用
- 严格的消息时序要求
- 需要摄像头消息同步
- 使用ASCM模块

## 八、代码调用流程

### 8.1 整体控制流程
```
1. selfdrive/controls/controlsd.py (主控制循环)
   ↓
2. selfdrive/car/interface.py (车辆接口)
   ↓
3. selfdrive/car/[brand]/carcontroller.py (品牌控制器)
   ↓
4. selfdrive/car/[brand]/[brand]can.py (CAN消息打包)
   ↓
5. opendbc/can/packer.py (使用DBC打包)
   ↓
6. panda (通过USB发送到CAN总线)
```

### 8.2 典型update()调用
```python
# 在controlsd.py中每个控制周期（50Hz）调用
def controlsd_thread():
    while True:
        # 1. 读取传感器数据
        CS = car_interface.update()

        # 2. 计算控制指令
        CC = planner.update(CS)

        # 3. 发送控制命令
        can_sends = car_controller.update(CC, CS)

        # 4. 发送到CAN总线
        can_interface.send(can_sends)
```

def update(self, CC, CS, now_nanos):
    # 获取转向指令
    limited_steer = rate_limit_steer(actuators.steer, self.last_steer)

## 总结

OpenPilot支持多个汽车品牌，每个品牌都有其特定的：
1. **CAN消息协议** - 定义在DBC文件中
2. **控制架构** - NIDEC/BOSCH（本田）、TSS/TSS2（丰田）等
3. **安全限制** - 转向力矩、速率、加速度限制
4. **通信机制** - 消息频率、校验方式、总线布局

核心控制通过统一的接口实现，但每个品牌的底层通信协议各不相同。理解这些差异对于开发、调试和扩展OpenPilot功能至关重要。
